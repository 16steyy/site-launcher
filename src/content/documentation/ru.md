# Кастомные темы 16Launcher

Кастомные темы позволяют изменять внешний вид интерфейса 16Launcher с помощью CSS. Тема может изменять цвета, фон, скругления, границы, акцентные элементы и другие визуальные свойства интерфейса.

В этой статье описано, как устанавливать, создавать, настраивать, удалять и распространять темы для 16Launcher. Дополнительно будет рассмотрено, где именно хранятся темы, как устроены их файлы, какие поля используются в metadata, как подключать изображения и шрифты, а также какие ошибки чаще всего возникают и как их избежать.

## 1. Что такое тема

Тема 16Launcher представляет собой отдельную папку с двумя обязательными файлами:

| Файл | Назначение |
| --- | --- |
| `theme.json` | Метаданные темы: название, автор, описание и версия |
| `style.css` | CSS-стили, изменяющие внешний вид интерфейса |

Дополнительно в папке темы можно размещать изображения, шрифты и другие ресурсы, необходимые для оформления.

Пример структуры темы:

```text
my-theme/
├── theme.json
├── style.css
├── background.png
└── fonts/
    └── MyFont.woff2
```

Файлы, дополнительные ресурсы и структура внутри папки могут отличаться в зависимости от назначения темы. Однако `theme.json` и `style.css` должны присутствовать обязательно.

Важно понимать, что тема не заменяет интерфейс 16Launcher целиком. Она применяется поверх стандартного оформления приложения и изменяет его с помощью CSS-правил. Это означает, что пользователь не меняет логическую структуру лаунчера, а лишь визуально перекрашивает или дополняет стандартный интерфейс.

Например, тема может:
* изменить основной акцентный цвет;
* изменить цвет и прозрачность панелей;
* настроить внешний вид кнопок;
* изменить скругление элементов;
* изменить оформление активных элементов боковой панели;
* добавить фоновые изображения;
* подключить пользовательские шрифты.

Это позволяет создавать как небольшие визуальные изменения, так и полностью переработанные цветовые схемы интерфейса. В одном и том же приложении можно использовать разные темы для разных настроений: минималистичную, тёмную, светлую, стеклянную, игровую, контрастную и т. д.

### Как работает кастомная тема

Кастомная тема в 16Launcher работает по принципу CSS-перекрытия. Лаунчер уже содержит базовую структуру и стили, а тема просто переопределяет отдельные селекторы, классы и CSS-переменные.

На практике это означает, что тема может:
* менять основной цвет акцента;
* перекрывать фон объектов;
* изменять тени, border, radius;
* делать отдельные панели полупрозрачными;
* изменять цвет текста и иконок;
* задавать альтернативные фоны, градиенты и спецэффекты.

При этом нельзя «переписать» весь интерфейс целиком, ведь 16Launcher все еще строит элементы по своей структуре. Тема должна работать внутри существующих компонентов приложения, а не заменять их вручную.

### Почему тема — это не просто CSS-файл

Файл `style.css` сам по себе не является полноценным «сценарием». Он должен учитывать, что 16Launcher использует собственные классы, переменные и структуру элементов. Именно поэтому тема почти всегда строится на базе уже существующих CSS-классов и переменных приложения, а не на случайных самописных селекторах.

Поэтому при разработке темы важно понимать:
* какие классы используются в интерфейсе;
* какие свойства можно переопределять;
* какие части интерфейса лучше не трогать;
* как обеспечить совместимость с обновлениями лаунчера.

## 2. Расположение тем

После установки 16Launcher темы хранятся в отдельном каталоге `themes`.

Расположение каталога зависит от операционной системы.

| Операционная система | Каталог тем |
| --- | --- |
| Windows | `%APPDATA%\16Launcher\themes\` |
| Linux | `~/.local/share/16Launcher/themes/` |
| macOS | `~/Library/Application Support/16Launcher/themes/` |

### Windows

На Windows каталог обычно находится по следующему пути:

```text
C:\Users\<ИмяПользователя>\AppData\Roaming\16Launcher\themes\
```

Вместо `<ИмяПользователя>` используется имя текущей учетной записи Windows.

### Linux

На Linux папка тем обычно расположена в пользовательском каталоге:

```text
~/.local/share/16Launcher/themes/
```

Это стандартное место для пользовательских данных приложений, и оно обычно уже доступно для записи без дополнительных прав.

### macOS

На macOS темы обычно хранятся в:

```text
~/Library/Application Support/16Launcher/themes/
```

Здесь также используется каталог пользовательских данных приложения, который не конфликтует с системными файлами.

### Структура каталога

Каждая тема должна находиться в отдельной папке:

```text
themes/
├── example-theme/
│   ├── theme.json
│   └── style.css
│
└── my-cool-theme/
    ├── theme.json
    ├── style.css
    └── background.png
```

Не следует помещать несколько тем в одну папку. Каждая тема должна иметь собственный каталог.

### Как открыть каталог тем

Каталог тем можно открыть непосредственно из интерфейса лаунчера:

**Настройки → Лаунчер → Кастомная тема → Открыть папку тем**

Этот способ рекомендуется использовать, если необходимо вручную установить, изменить или удалить тему.

Такой способ удобен тем, что:
* не нужно искать путь вручную;
* нет риска ошибиться в расположении папки;
* можно быстро открыть нужную тему для редактирования;
* проще управлять несколькими установленными темами.

### Важный момент про папки тем

Файлы темы должны лежать именно внутри папки темы, а не в корне каталога `themes` и не внутри нескольких вложенных директорий без необходимости. Если 16Launcher ищет темы в определенном каталоге, то каждая тема должна быть представлена отдельной папкой с корректной структурой.

## 3. Как включить тему

После установки тема появляется в списке доступных тем.

Чтобы включить тему:

1. Откройте **Настройки**.
2. Перейдите во вкладку **Лаунчер**.
3. Найдите раздел **Кастомизация**.
4. Откройте пункт **Кастомная тема**.
5. Выберите нужную тему.

Тема применяется непосредственно после выбора.

Чтобы вернуть стандартное оформление 16Launcher, выберите **Стандартная**.

Выбранная тема сохраняется в настройках лаунчера, поэтому повторно выбирать ее после каждого запуска приложения не требуется.

### Как именно применяется тема

Когда пользователь выбирает тему, 16Launcher сохраняет ее ID или имя в пользовательских настройках. После запуска программы она снова загружает активную тему и применяет CSS к интерфейсу.

Если тема была изменена вручную в папке после установки, то эффект может не отобразиться сразу, пока файл не будет перезагружен или пока тема не будет пересоздана/выбрана заново. Подробнее об этом будет рассказано ниже в разделе про редактирование CSS.

### Стандартная тема

Выбор пункта **Стандартная** обычно означает откат к исходному оформлению лаунчера. При этом сама папка темы не удаляется, а просто перестает использоваться. Это удобно, если нужно быстро сравнить оформление без полной потери созданной темы.

## 4. Установка темы

Установить тему можно несколькими способами.

### 4.1. Импорт ZIP-архива

Импорт ZIP является наиболее простым способом установки готовой темы.

Порядок установки:

1. Откройте настройки кастомных тем.
2. Нажмите **Импорт ZIP**.
3. Выберите ZIP-архив с темой.
4. Дождитесь завершения импорта.
5. Выберите установленную тему в списке.

После успешного импорта тема появляется в каталоге `themes` и становится доступной в списке тем.

### Требования к ZIP-архиву

В архиве должны присутствовать:

```text
theme.json
style.css
```

Файлы могут находиться непосредственно в корне архива:

```text
ocean-mint.zip
├── theme.json
└── style.css
```

Также они могут находиться внутри одной общей папки:

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    └── style.css
```

Оба варианта поддерживаются.

При наличии дополнительных ресурсов структура может выглядеть следующим образом:

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    ├── style.css
    ├── background.png
    └── fonts/
        └── MyFont.woff2
```

Для имени ZIP-архива рекомендуется использовать латинские символы, цифры, дефисы и символы подчеркивания.

Например:

```text
ocean-mint.zip
dark-glass.zip
baza-emerald.zip
```

### Определение ID при импорте

При импорте ZIP идентификатор темы формируется на основе имени ZIP-файла с очисткой недопустимых символов.

Например:

```text
Ocean Mint.zip
```

может получить ID:

```text
ocean-mint
```

Поэтому рекомендуется заранее использовать корректное имя архива.

Это важно, потому что ID темы часто используется в системных путях, в названиях папок и в логике выбора темы. Если архив назван некорректно, то папка темы может быть создана с неочевидным или неудобным идентификатором. В дальнейшем это затрудняет поиск, удаление и обновление темы.

### Что происходит после импорта

После импорта 16Launcher обычно:
* создает папку темы в каталоге `themes`;
* копирует файлы внутри нее;
* распознает `theme.json` и `style.css`;
* добавляет тему в список доступных тем.

Если тема нормально распозналась, она сразу становится доступной для выбора. Если в архиве есть проблемы, например, отсутствует `style.css`, или JSON поврежден, то тема может не появиться или будет отображаться некорректно.

## 5. Установка темы вручную

Тему также можно установить без использования импорта ZIP.

Для этого:

1. Создайте отдельную папку для темы.
2. Добавьте в нее `theme.json` и `style.css`.
3. При необходимости добавьте изображения, шрифты и другие ресурсы.
4. Скопируйте папку в каталог `themes`.
5. Откройте настройки 16Launcher.
6. Перейдите в раздел кастомных тем.
7. Выберите установленную тему.

Например:

```text
themes/
└── ocean-mint/
    ├── theme.json
    ├── style.css
    └── background.png
```

Если список тем уже был открыт во время копирования файлов, может потребоваться повторно открыть вкладку **Лаунчер** или перезапустить 16Launcher.

### Когда вручную копировать папку лучше ZIP-импорта

Ручной способ полезен, когда:
* тема находится в разработке;
* нужно быстро внести правки без повторного архива;
* вы хотите создать тему под конкретный проект или локальный набор ресурсов;
* нужна тонкая настройка файлов внутри папки.

В то же время ZIP-импорт удобнее для распространения и передачи темы другим людям, потому что весь комплект темы легко упаковать в один архив.

### Важность правильной структуры папки

Файлы внутри темы должны находиться не просто «где-то рядом», а в строго определенной папке темы. Если оставить файлы в корне `themes` без папки, 16Launcher может их не распознать. То же самое касается вложенных директорий, если `theme.json` и `style.css` находятся глубже, чем ожидается.

Основное правило простое: каждая тема — это отдельная папка, а внутри нее — `theme.json` и `style.css`.

## 6. Создание темы из 16Launcher

16Launcher позволяет создать новую тему непосредственно из настроек.

Порядок действий:

1. Откройте **Настройки → Лаунчер → Кастомная тема**.
2. Нажмите **Создать тему**.
3. Укажите название темы.
4. 16Launcher создаст каталог темы.
5. В каталоге будут созданы стандартные `theme.json` и `style.css`.
6. Нажмите **Редактировать CSS**, чтобы открыть `style.css` во внешнем редакторе.
7. Внесите необходимые изменения.
8. Сохраните файл.

После изменения CSS переключите тему или повторно выберите ее, чтобы применить изменения.

### Как создается тема

При создании темы 16Launcher сам формирует папку с именем, производным от указанного названия, а также создает базовые файлы. Это удобно, потому что:
* нет необходимости вручную создавать структуру;
* сразу есть шаблон для начала работы;
* можно быстро тестировать идеи;
* легко сохранить тему и потом упаковать в ZIP.

### Что делать после сохранения CSS

После редактирования файла многие пользователи ожидают, что изменения применятся мгновенно. Но в текущей версии 16Launcher это не всегда происходит автоматически. Поэтому важно понимать, что редактор CSS не является живым preview-сервисом.

### Обновление темы после изменения CSS

В текущей версии 16Launcher нет автоматического отслеживания изменений `style.css` в реальном времени.

Поэтому после редактирования файла необходимо:

* переключиться на другую тему и обратно;
* либо перезапустить лаунчер.

Это особенно важно при разработке темы, поскольку сохранение файла в текстовом редакторе само по себе не гарантирует немедленного обновления интерфейса.

Когда тема активна, 16Launcher загружает CSS один раз. Если файл изменился, пользовательская среда не всегда понимает, что нужно перезагрузить стили. Поэтому для удобной разработки нужно помнить о цикле:
1. отредактировать CSS;
2. сохранить файл;
3. переключить тему или перезапустить приложение;
4. проверить результат.

### Рекомендуемая практика разработки

На ранних этапах работы удобно:
* создавать небольшие изменения;
* проверять их после каждого сохранения;
* применять один стиль за раз;
* использовать минимальный набор селекторов;
* избегать резких глобальных переопределений, которые могут сломать интерфейс.

## 7. Идентификатор и отображаемое имя темы

У каждой темы есть два разных имени:

1. **ID темы** — техническое имя каталога;
2. **Название темы** — имя, отображаемое пользователю.

Эти значения используются для разных целей и не должны рассматриваться как одно и то же.

### 7.1. ID темы

ID — это имя папки темы на диске.

Например:

```text
ocean-mint/
```

где `ocean-mint` является ID темы.

Рекомендуемые правила:

* использовать латинские буквы;
* использовать цифры при необходимости;
* использовать `-` и `_`;
* не использовать пробелы;
* не использовать специальные символы;
* предпочтительно использовать нижний регистр;
* использовать короткое и понятное название.

Рекомендуемые варианты:

```text
ocean-mint
dark-glass
baza-emerald
my-theme
theme_01
```

Нежелательные варианты:

```text
Моя тема!!!
theme 1
Cool Theme (final)
тема-новая
```

При создании темы через кнопку **Создать тему** 16Launcher автоматически формирует ID на основе указанного названия.

Например:

```text
Ocean Mint
```

преобразуется в:

```text
ocean-mint
```

При импорте ZIP идентификатор формируется на основе имени ZIP-архива.

### 7.2. Отображаемое название

Отображаемое название задается в поле `name` файла `theme.json`.

В отличие от ID, это имя предназначено непосредственно для пользователя.

В нем можно использовать:
* кириллицу;
* пробелы;
* заглавные буквы;
* специальные символы;
* другие символы, поддерживаемые UTF-8.

Например:

```json
{
  "name": "Изумрудный океан",
  "author": "BAZA",
  "description": "Зелёно-бирюзовая тема для 16Launcher",
  "version": "1.0"
}
```

В этом случае:
* ID темы может быть `ocean-mint`;
* отображаемое название — `Изумрудный океан`.

### Почему важно различать ID и имя

Это особенно важно при публикации тем, обмене темами между пользователями и дальнейшей поддержке. Папка на диске должна быть удобной для системной работы, а пользовательское имя — понятным для людей.

Например, каталог `dark-glass` может называться так на диске, но в интерфейсе пользователю может показываться название **Стеклянная тьма**, **Темное стекло** или **Midnight Glass**. Это делает тему удобнее и более эстетичной без нарушения технической структуры.

## 8. Формат `theme.json`

Файл `theme.json` содержит метаданные темы.

Минимальный пример:

```json
{
  "name": "Моя тема",
  "author": "Ваше имя",
  "description": "Краткое описание темы",
  "version": "1.0"
}
```

Поддерживаемые поля:

| Поле | Назначение |
| --- | --- |
| `name` | Название темы в интерфейсе |
| `author` | Автор темы |
| `description` | Краткое описание |
| `version` | Версия темы |

Все поля являются необязательными. Однако рекомендуется указывать как минимум `name`, `author`, `description` и `version`, особенно если тема предназначена для распространения.

Если `name` не указан или пуст, в интерфейсе может использоваться имя каталога темы.

### Что такое metadata темы

Файл `theme.json` нужен не только для приятного отображения. Он также служит описанием темы, используемым в интерфейсе, для идентификации и для удобства управления темами. Если тема распространяется между пользователями, полезно, чтобы у каждого архива были понятные метаданные: название, автор, версия, краткое описание.

### Версия темы

Для версии рекомендуется использовать понятный формат:

```text
1.0
```

или:

```text
1.2.0
```

При значительных изменениях темы версию рекомендуется увеличивать, чтобы пользователям было проще отличать новые версии от предыдущих.

Это особенно важно, если тема загружается, обновляется или распространяется между несколькими пользователями. Согласованный формат версий позволяет лучше отслеживать изменения, сравнивать обновления и понимать, совместима ли тема с текущей версией лаунчера.

### Кодировка файла

`theme.json` должен быть сохранен в кодировке UTF-8.

При использовании кириллицы это особенно важно. Неправильная кодировка файла может привести к некорректному отображению названия, автора или описания.

Проблемы с UTF-8 часто возникают, если файл сохранен в ANSI, UTF-16 или другой кодировке. В результате может получиться:
* замена символов;
* нечитаемые строки;
* искаженные названия;
* ошибки при загрузке.

Поэтому перед публикацией темы всегда лучше убедиться, что файл открыт и сохранен как UTF-8.

## 9. Формат `style.css`

Основная настройка внешнего вида темы выполняется в файле `style.css`.

Это обычный CSS-файл, поэтому для создания темы можно использовать стандартные CSS-свойства, селекторы, переменные, градиенты, изображения, шрифты и другие возможности CSS, доступные в интерфейсе 16Launcher.

Простейший пример:

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
  border-color: rgba(16, 185, 129, 0.35) !important;
}

.accent-bg {
  background: linear-gradient(135deg, #34d399, #059669) !important;
}

.interactive-press {
  border-radius: 16px !important;
}

.sidebar-icon-active {
  color: #6ee7b7 !important;
}
```

### Почему CSS в теме называется `style.css`

Потому что 16Launcher ожидает именно такой файл как основной источник пользовательских стилей. Внутри него описываются правила, которые переопределяют стандартное оформление.

### Как понимать CSS в теме

В теме можно использовать:
* селекторы классов;
* CSS-переменные;
* псевдоклассы;
* `background`, `color`, `border`, `border-radius`, `opacity`, `box-shadow`;
* `url(...)` для изображений;
* `@font-face` для пользовательских шрифтов.

Однако важно помнить, что 16Launcher может использовать собственные классы с более высоким приоритетом. Поэтому некоторые значения могут требовать `!important`, чтобы применяться корректно.

### Использование `!important`

Стандартные стили 16Launcher могут иметь более высокий приоритет, чем правила пользовательской темы.

В таких случаях может потребоваться `!important`.

Например:

```css
.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
}
```

Не следует использовать `!important` абсолютно для всех свойств без необходимости. Сначала рекомендуется проверить, применяется ли обычное CSS-правило.

Проблема в том, что слишком много `!important` может:
* сделать код сложнее для поддержки;
* затруднить редактирование;
* конфликтовать с обновлениями приложения;
* переопределять неожиданные элементы.

Поэтому `!important` следует использовать точечно, там, где действительно есть конфликт приоритетов.

## 10. Основные селекторы 16Launcher

В темах можно использовать следующие классы и CSS-переменные.

| Селектор | Назначение |
| --- | --- |
| `.glass-panel` | Основные стеклянные панели интерфейса |
| `.glass-chip` | Небольшие чипы и бейджи |
| `.interactive-press` | Кликабельные элементы и кнопки |
| `.accent-bg` | Акцентный фон, включая некоторые кнопки |
| `.accent-border` | Акцентная граница |
| `.accent-chip` | Акцентные чипы |
| `.sidebar-icon-active` | Активная иконка боковой панели |
| `:root` | Корневой элемент для определения CSS-переменных |
| `--accent-color` | Основной акцентный цвет |

Набор доступных классов может изменяться вместе с развитием 16Launcher. Поэтому при создании сложной темы рекомендуется проверять ее работу после обновления лаунчера.

### Как работать с селекторами

Если тема должна изменить общий фон панелей, удобно использовать `.glass-panel`. Если нужно выделить кнопку, обычно будет достаточно `.interactive-press` или `.accent-bg`. Для размещения иконок, активных элементов боковой панели — `.sidebar-icon-active`.

### Что делать при отсутствии нужного класса

Если нужного класса нет, можно использовать более общие селекторы, но важно помнить, что глобальные правила могут случайно затронуть не только тот элемент, который вы хотели изменить.

Например, можно задать цвет для всех кнопок или изменить общий фон всей панели, но это может повлиять на несколько интерфейсных частей. Поэтому для аккуратной темы лучше:
* использовать конкретные классы;
* комбинировать селекторы;
* проверять результат после применения стилизации;
* избегать «перекраски всего приложения».

### CSS-переменные

Переменные применяются через `:root`:

```css
:root {
  --accent-color: #10b981;
}
```

Это очень удобно, потому что:
* цвет можно изменить в одном месте;
* не нужно переписывать десятки правил;
* проще поддерживать тему;
* проще создавать вариации палитры.

При этом не все элементы в 16Launcher обязательно используют только одну переменную. Иногда часть интерфейса подстраивается под классы напрямую, а другая — через собственные переменные.

## 11. Использование изображений

В тему можно добавить собственные изображения.

Например:

```text
ocean-mint/
├── theme.json
├── style.css
└── background.png
```

После этого изображение можно подключить из `style.css`:

```css
.glass-panel {
  background-image: url(background.png) !important;
  background-size: cover !important;
}
```

Путь к ресурсу должен быть относительным.

Если изображение находится во вложенной папке:

```text
ocean-mint/
├── theme.json
├── style.css
└── images/
    └── background.png
```

используйте:

```css
.glass-panel {
  background-image: url(images/background.png) !important;
}
```

16Launcher обрабатывает относительные `url(...)` и преобразует их в рабочие пути к ресурсам темы.

### Почему нельзя использовать абсолютные пути

Для локальных файлов темы не следует использовать абсолютные пути конкретного компьютера, например:

```text
C:\Users\User\Desktop\background.png
```

Такие пути не будут работать после передачи темы другому пользователю.

Абсолютные пути:
* привязаны к конкретному устройству;
* зависят от имени пользователя;
* зависят от расположения файлов;
* не переносятся на другой компьютер;
* нарушают принцип переносимости темы.

### Что важно учитывать при работе с изображениями

При использовании фоновых изображений стоит помнить:
* размер файла не должен быть слишком большим;
* для адаптивного интерфейса лучше использовать подходящее разрешение;
* можно использовать `background-size: cover` для заполнения области;
* лучше использовать фоновые изображения с сохранением общей стилистики темы;
* для активных элементов картинки лучше не перегружать интерфейс.

Иногда лучше сделать сочетание:
* полупрозрачный фон;
* мягкий градиент;
* небольшой паттерн или текстуру;
чем использовать слишком тяжелое изображение, которое будет занимать много ресурсов.

## 12. Использование пользовательских шрифтов

В папку темы можно добавить собственные файлы шрифтов.

Например:

```text
ocean-mint/
├── theme.json
├── style.css
└── fonts/
    └── MyFont.woff2
```

Подключить шрифт можно с помощью `@font-face`:

```css
@font-face {
  font-family: "MyFont";
  src: url(fonts/MyFont.woff2);
}

body {
  font-family: "MyFont", sans-serif;
}
```

Для распространения темы рекомендуется убедиться, что лицензия используемого шрифта разрешает его распространение вместе с другими файлами.

### Почему важно следить за лицензией

Пользовательские шрифты часто являются частью дизайна темы, но не все их можно распространять без ограничений. Если шрифт лицензирован под коммерческое использование или запрещает включение в архивы, это может привести к юридическим вопросам.

Рекомендуется:
* использовать шрифты, которые можно распространять;
* сохранять лицензию в архиве, если это требуется;
* не использовать чужие ресурсы без разрешения;
* изначально проверять возможности распространения.

### Когда шрифты полезны

Пользовательские шрифты особенно хорошо работают, если тема:
* пытается имитировать определенный стиль на основе интерфейса;
* имеет большое декоративное оформление;
* использует акцентный заголовок или необычный визуальный язык.

Но даже хорошее оформление может ухудшиться, если шрифт слишком тяжелый или нечитабельный в интерфейсе лаунчера. Поэтому важно соблюдать баланс между декоративностью и функциональностью.

## 13. Рекомендации по созданию тем

При разработке темы рекомендуется придерживаться следующих правил:

### Используйте CSS-переменные

Если тема использует несколько элементов одного цвета, удобно определить цвет один раз:

```css
:root {
  --accent-color: #10b981;
}
```

Это упрощает дальнейшее изменение цветовой схемы.

Использование переменных удобно потому, что:
* можно менять один цвет и сразу обновлять все связанные элементы;
* проще делать alternate-темы;
* проще поддерживать одну палитру в нескольких правилах;
* легче ориентироваться в коде.

### Не изменяйте системные файлы 16Launcher

Все изменения должны находиться внутри собственной папки темы.

Не рекомендуется изменять файлы самого приложения для создания визуального оформления.

Это важно по двум причинам:
1. изменения в системных файлах могут быть потеряны после обновления лаунчера;
2. такие изменения часто нарушают целостность приложения.

Тема должна быть изолирована от основного кода проекта и располагаться в отдельном каталоге, который 16Launcher знает и поддерживает.

### Используйте относительные пути

Для изображений и шрифтов используйте:

```css
url(images/background.png)
```

а не пути, привязанные к конкретному компьютеру.

Это одно из главных правил распространения темы. Только так тема может быть переслана другому пользователю и корректно загружена на другом устройстве.

### Проверяйте тему после установки

Перед распространением рекомендуется проверить:
* отображение всех панелей;
* кнопки;
* активные элементы;
* фоновые изображения;
* пользовательские шрифты;
* работу темы после повторного запуска;
* корректность ZIP-архива.

При работе с кастомной темой важно проверять не только то, что файл подключается, но и то, что интерфейс выглядит корректно в целом. Нельзя ограничиваться проверкой одного окрашенного элемента — нужно убедиться в целостности оформления.

### Не делайте чрезмерно сложную тему в самом начале

Самая частая ошибка новичков — попытка сразу сделать полноценный, «премиум» дизайн со сложными эффектами, тенями, анимацией и количеством ресурсов. Это часто приводит к:
* сложному отладочному процессу;
* конфликтам CSS;
* проблемам с чтением интерфейса;
* трудностям после обновления лаунчера.

Лучше начинать с малого:
* сменить основной цвет;
* поправить фоны;
* решить проблему с читаемостью;
* затем добавить детали.

## 14. Как поделиться темой

Для распространения тему рекомендуется упаковать в ZIP-архив.

Порядок действий:

1. Откройте каталог темы.
2. Убедитесь, что присутствуют `theme.json` и `style.css`.
3. Проверьте дополнительные изображения и шрифты.
4. Создайте ZIP-архив.
5. Передайте архив другим пользователям.

Можно архивировать непосредственно папку темы:

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    ├── style.css
    └── background.png
```

Также допустим архив, содержащий файлы темы непосредственно в корне:

```text
ocean-mint.zip
├── theme.json
└── style.css
```

В качестве имени архива рекомендуется использовать ID темы:

```text
ocean-mint.zip
```

Это упрощает идентификацию темы и позволяет корректно сформировать ее ID при импорте.

Получатель сможет установить тему через:

**Настройки → Лаунчер → Кастомная тема → Импорт ZIP**

### Почему архивирование так важно

ZIP-архив — это универсальный способ передачи темы. Он:
* упаковывает все файлы в один объект;
* позволяет быстро отправить тему по почте, в чат, в сообщество или на форум;
* сохраняет структуру папки;
* упрощает установку без ручного копирования данных.

### Рекомендации по упаковке

Перед отправкой темы рекомендуется:
* проверить, что внутри архива нет лишних файлов;
* убедиться, что все пути сохраняются корректно;
* убедиться, что не включены временные или служебные файлы;
* проверить корректность имени ZIP;
* проверить, что `theme.json` и `style.css` находятся там, где ожидается.

## 15. Удаление темы

Удалить установленную тему можно непосредственно из интерфейса 16Launcher.

1. Откройте список кастомных тем.
2. Выберите тему.
3. Нажмите **Удалить тему**.
4. Подтвердите удаление.

Также папку темы можно удалить вручную из каталога `themes`.

### Когда удаление вручную может пригодиться

Удаление вручную удобно, если:
* нужно быстро очистить каталог тем;
* тема больше не используется;
* нужно исправить проблему с поврежденной папкой;
* нужно удалить снимок темы, который не отображается в интерфейсе.

Однако при удалении вручную важно убедиться, что:
* папка действительно не нужна;
* тема не используется в качестве активной;
* после удаления приложение не требует повторного выбора темы.

### Встроенные темы

Некоторые темы, поставляемые вместе с 16Launcher, могут автоматически восстанавливаться при следующем запуске приложения.

Например, если удалить встроенную тему `example-theme`, лаунчер может повторно скопировать ее из встроенных ресурсов, если обнаружит, что соответствующей папки больше нет.

Это означает, что встроенные темы не всегда являются «постоянными пользовательскими темами» и могут быть перечитываемыми из базовых ресурсов приложения. Поэтому пользователю важно понимать разницу между:
* пользовательскими темами, установленными вручную;
* встроенными темами, которые могут быть восстановлены автоматически.

## 16. Типичные проблемы

### Тема не появляется в списке

Проверьте следующее:
* существует ли папка темы;
* присутствует ли `theme.json`;
* присутствует ли `style.css`;
* находятся ли эти файлы непосредственно в папке темы;
* корректно ли сформирован JSON;
* находится ли тема в правильном каталоге `themes`.

Правильная структура:

```text
themes/
└── my-theme/
    ├── theme.json
    └── style.css
```

Если файлов не хватает, приложение просто не сможет распознать тему. В такой ситуации важно проверить, нет ли ошибок в структуре каталога.

### После импорта получился неправильный ID

При импорте ZIP ID формируется на основе имени архива.

Например:

```text
My Cool Theme.zip
```

может получить ID, отличающийся от ожидаемого.

Если необходимо изменить ID, переименуйте ZIP-архив и импортируйте тему повторно.

Иногда пользователю хочется, чтобы ID совпадал с названием темы. Это возможно, но при импорте ID формируется автоматически и исходя из имени файла. Поэтому корректный выбор имени архива — один из самых простых способов избежать проблем.

### CSS не применяется

Возможные причины:
1. Ошибка в CSS-селекторе.
2. Стандартное правило имеет более высокий приоритет.
3. Не используется `!important`, когда он необходим.
4. Тема не была повторно применена после изменения файла.
5. Изменения не были сохранены в редакторе.

После изменения `style.css` переключите тему или перезапустите 16Launcher.

Это одна из самых частых проблем. Пользователь изменяет CSS, но ничего не меняется, потому что:
* селектор по факту не совпадает с нужным элементом;
* старое правило перекрывает новое;
* тема не была обновлена;
* редактор не сохранил изменения;
* файл был изменен в другой кодировке или другой папке.

### Изображение не отображается

Проверьте:
* существует ли файл;
* правильно ли указан относительный путь;
* совпадает ли регистр букв в имени файла;
* находится ли файл внутри папки темы.

Например:

```css
background-image: url(images/background.png);
```

требует наличия файла:

```text
images/background.png
```

Также важно помнить, что регистр символов в имени файла чувствителен на некоторых системах. Если файл называется `Background.png`, а в CSS указано `background.png`, то загрузка может не состояться.

### Тема исчезла после сброса настроек

Сброс настроек может снять выбранную тему или вернуть стандартное оформление.

При этом папка самой темы в каталоге `themes` обычно остается.

В таком случае откройте список кастомных тем и выберите тему повторно.

Сброс настроек не обязательно означает удаление темы. Обычно он сбрасывает активный выбор и список пользовательских параметров. То есть фактическая тема остается на диске, но больше не активна.

## 17. Рекомендуемая структура готовой темы

Для распространения рекомендуется использовать следующую структуру:

```text
ocean-mint/
├── theme.json
├── style.css
├── images/
│   └── background.png
└── fonts/
    └── MyFont.woff2
```

Пример `theme.json`:

```json
{
  "name": "Изумрудный океан",
  "author": "BAZA",
  "description": "Зелёно-бирюзовая тема для 16Launcher",
  "version": "1.0.0"
}
```

Пример `style.css`:

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
  border-color: rgba(16, 185, 129, 0.35) !important;
}

.accent-bg {
  background: linear-gradient(135deg, #34d399, #059669) !important;
}

.accent-border {
  border-color: rgba(16, 185, 129, 0.5) !important;
}

.interactive-press {
  border-radius: 16px !important;
}

.sidebar-icon-active {
  color: #6ee7b7 !important;
}
```

### Почему такая структура считается хорошей

Потому что она:
* логична;
* понятна пользователям;
* легко распространяется;
* удобно редактируется;
* позволяет хранить разные ресурсы отдельно;
* не создает путаницу при импорте;
* соответствует повсеместному стандарту пакетов тем.

## 18. Чеклист перед публикацией темы

Перед передачей темы другим пользователям рекомендуется проверить следующие пункты:

* [ ] Папка темы имеет корректный ID, например `my-theme`.
* [ ] В папке присутствует `theme.json`.
* [ ] В папке присутствует `style.css`.
* [ ] `theme.json` сохранен в кодировке UTF-8.
* [ ] В `theme.json` указано понятное название темы.
* [ ] Указан автор темы.
* [ ] Указана версия темы.
* [ ] Указано краткое описание.
* [ ] Все изображения и шрифты находятся внутри папки темы.
* [ ] В CSS используются относительные пути к ресурсам.
* [ ] Тема корректно отображается в 16Launcher.
* [ ] Все необходимые CSS-правила применяются.
* [ ] Тема повторно применяется после перезапуска лаунчера.
* [ ] ZIP-архив корректно импортируется через **Импорт ZIP**.
* [ ] В архив не включены лишние файлы, не относящиеся к теме.

### Почему важно проверять перед публикацией

Публикация темы — это не просто «сохранить и отправить». Даже небольшая ошибка в структуре, пути, кодировке или селекторе может сделать тему непригодной для использования. Чеклист помогает вовремя обнаружить такие проблемы и избежать неприятных ситуаций.

## 19. Быстрый старт

Создать первую тему можно за несколько минут.

### Шаг 1. Создайте тему

Откройте:

**Настройки → Лаунчер → Кастомная тема → Создать тему**

Введите, например:

```text
Моя тема
```

16Launcher создаст каталог темы и необходимые файлы.

### Шаг 2. Откройте CSS

Нажмите **Редактировать CSS**.

Откроется файл:

```text
style.css
```

### Шаг 3. Добавьте стили

Например:

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
}

.accent-bg {
  background: #10b981 !important;
}
```

Сохраните файл.

### Шаг 4. Примените изменения

Переключите тему на **Стандартная**, затем снова выберите созданную тему.

Также можно полностью перезапустить 16Launcher.

После этого изменения CSS должны примениться.

### Шаг 5. Подготовьте тему к распространению

Когда оформление будет готово, откройте папку темы и упакуйте ее в ZIP-архив.

Рекомендуемый вариант:

```text
my-theme.zip
└── my-theme/
    ├── theme.json
    └── style.css
```

Полученный архив можно передать другим пользователям. Для установки им достаточно использовать **Импорт ZIP**.

### Как ориентироваться в процессе

Для начала лучше всего:
* поменять цвет акцента;
* сделать панели более темными или прозрачными;
* изменить border-radius;
* проверить, насколько читаемы элементы;
* затем переходить к более сложным эффектам.

Разработка темы — это постепенная настройка. Гораздо проще добиться хорошего результата, если начинать с базовых изменений и проверять их визуально, а не пытаться сделать все сразу.

## 20. Примеры готовых тем

В составе 16Launcher могут присутствовать демонстрационные и тестовые темы.

Например:

* `example-theme` — демонстрационная фиолетовая тема;
* `baza-emerald` — тестовая изумрудная тема.

Эти темы можно использовать в качестве примера структуры и оформления при создании собственных тем.

### Почему полезно смотреть на примеры

Примеры тем помогают:
* понять, как устроены папки;
* увидеть типовые CSS-правила;
* понять, какой стиль совпадает с интерфейсом 16Launcher;
* лучше ориентироваться в названиях классов;
* быстрее начать собственную разработку.

Но важно понимать, что пример — это не окончательный стандарт. 16Launcher постоянно развивается, и набор селекторов и классов может изменяться. Поэтому, даже если пример выглядит красиво, следует проверять его совместимость с текущей версией лаунчера.

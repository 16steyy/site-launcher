# 16Launcher 自定义主题

自定义主题允许你使用 CSS 修改 16Launcher 的界面外观。主题可以更改颜色、背景、圆角、边框、强调元素以及界面的其他视觉属性。

本文介绍了如何安装、创建、配置、删除和分发 16Launcher 的主题。此外，还将详细说明主题的具体存储位置、文件组织方式、metadata 中使用的字段、如何引入图像和字体，以及最常见的错误和避免方法。

## 1. 什么是主题

16Launcher 的主题是一个独立的文件夹，包含两个必须的文件：

| 文件 | 用途 |
| --- | --- |
| `theme.json` | 主题的元数据：名称、作者、描述和版本 |
| `style.css` | 修改界面外观的 CSS 样式 |

此外，在主题文件夹中还可以放置设计所需的图像、字体和其他资源。

主题结构示例：

```text
my-theme/
├── theme.json
├── style.css
├── background.png
└── fonts/
    └── MyFont.woff2
```

文件夹内的文件、附加资源和结构可能会因主题用途的不同而有所差异。但是，`theme.json` 和 `style.css` 必须存在。

需要明确的是，主题并不能完全替换 16Launcher 的界面。它应用于应用程序的默认样式之上，并通过 CSS 规则对其进行重写。这意味着用户并非改变启动器的逻辑结构，而仅仅是在视觉上重绘或补充标准界面。

例如，主题可以：
* 更改主强调色；
* 更改面板的颜色和透明度；
* 自定义按钮的外观；
* 更改元素的圆角；
* 改变侧边栏活动元素的设计；
* 添加背景图像；
* 引入自定义字体。

这既允许做出微小的视觉调整，也能够打造完全重新设计的界面配色方案。在同一个应用程序中，你可以针对不同的心情使用不同的主题：极简风、暗黑风、明亮风、玻璃风、游戏风、高对比度风等。

### 自定义主题的工作原理

16Launcher 中的自定义主题基于 CSS 覆盖机制运作。启动器本身已包含基础结构和样式，而主题只需重新定义特定的选择器、类和 CSS 变量。

在实际应用中，这意味着主题可以：
* 替换主强调色；
* 覆盖对象的背景；
* 修改阴影、边框 (border) 和圆角 (radius)；
* 使特定面板半透明；
* 更改文本和图标的颜色；
* 设置替代背景、渐变和特殊效果。

同时，你无法“重写”整个界面，因为 16Launcher 仍然按照自己的结构构建元素。主题必须在应用程序现有的组件内部生效，而不是手动替换它们。

### 为什么主题不仅仅是一个 CSS 文件

`style.css` 文件本身并不是一个完整的“脚本”。它必须考虑到 16Launcher 使用了自己的类、变量和元素结构。正是因为这一点，主题几乎总是基于应用程序现有的 CSS 类和变量来构建，而不是随意使用自定义的选择器。

因此，在开发主题时，了解以下内容非常重要：
* 界面中使用了哪些类；
* 哪些属性可以被覆盖；
* 界面的哪些部分最好不要动；
* 如何确保与启动器更新的兼容性。

## 2. 主题的存储位置

安装 16Launcher 后，主题存储在单独的 `themes` 目录中。

该目录的位置取决于操作系统：

| 操作系统 | 主题目录 |
| --- | --- |
| Windows | `%APPDATA%\16Launcher\themes\` |
| Linux | `~/.local/share/16Launcher/themes/` |
| macOS | `~/Library/Application Support/16Launcher/themes/` |

### Windows

在 Windows 系统上，该目录通常位于以下路径：

```text
C:\Users\<用户名>\AppData\Roaming\16Launcher\themes\
```

将 `<用户名>` 替换为当前 Windows 账户的名称。

### Linux

在 Linux 系统上，主题文件夹通常位于用户目录中：

```text
~/.local/share/16Launcher/themes/
```

这是用户应用数据的标准位置，通常无需额外权限即可直接写入。

### macOS

在 macOS 系统上，主题通常存储在：

```text
~/Library/Application Support/16Launcher/themes/
```

此处同样使用的是用户应用数据目录，不会与系统文件发生冲突。

### 目录结构

每个主题都必须位于独立的文件夹中：

```text
themes/
├── example-theme/
│   ├── theme.json
│   └── style.css
│
└── my-cool-theme/
    ├── theme.json
    ├── style.css
    └── background.png
```

请勿将多个主题放在同一个文件夹中。每个主题必须拥有自己的目录。

### 如何打开主题目录

可以直接从启动器界面打开主题目录：

**设置 → 启动器 → 自定义主题 → 打开主题文件夹**

如果需要手动安装、修改或删除主题，建议使用此方法。

这种方式的好处在于：
* 无需手动查找路径；
* 不存在文件夹位置出错的风险；
* 可以快速打开所需主题进行编辑；
* 更轻松地管理已安装的多个主题。

### 关于主题文件夹的重要提示

主题文件必须严格放置在主题文件夹内部，而不是 `themes` 目录的根目录下，也不要无故嵌套多层子目录。如果 16Launcher 在特定目录中查找主题，则每个主题都应表现为一个结构正确的独立文件夹。

## 3. 如何启用主题

安装完成后，主题会显示在可用主题列表中。

要启用主题：

1. 打开 **设置**。
2. 切换到 **启动器** 标签页。
3. 找到 **个性化** 区域。
4. 打开 **自定义主题** 选项。
5. 选择所需的主题。

选择后，主题将立即生效。

若要恢复 16Launcher 的默认外观，请选择 **默认**。

选中的主题会保存在启动器设置中，因此无需在每次启动应用程序后重新选择。

### 主题是如何应用的

当用户选择某个主题时，16Launcher 会在其用户设置中保存该主题的 ID 或名称。程序启动后，会再次加载当前活动的主题并将 CSS 应用于界面。

如果在安装后手动修改了文件夹中的主题，效果可能不会立即显现，直到文件被重新加载或主题被重新创建/重新选择。关于这一点，将在下文编辑 CSS 的章节中详细说明。

### 默认主题

选择 **默认** 选项通常意味着还原为启动器的初始外观。此时，主题文件夹本身不会被删除，只是停止使用。如果你想快速对比外观而不丢失已创建的主题，这会非常方便。

## 4. 安装主题

可以通过几种方式安装主题。

### 4.1. 导入 ZIP 压缩包

导入 ZIP 是安装现成主题最简单的方法。

安装步骤：

1. 打开自定义主题设置。
2. 点击 **导入 ZIP**。
3. 选择包含主题的 ZIP 压缩包。
4. 等待导入完成。
5. 在列表中选择已安装的主题。

成功导入后，主题将出现在 `themes` 目录中，并在主题列表中变为可用状态。

### 对 ZIP 压缩包的要求

压缩包内必须包含：

```text
theme.json
style.css
```

文件可以直接位于压缩包的根目录下：

```text
ocean-mint.zip
├── theme.json
└── style.css
```

它们也可以位于一个统一的文件夹内部：

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    └── style.css
```

两种形式均支持。

如果存在附加资源，结构可能如下所示：

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    ├── style.css
    ├── background.png
    └── fonts/
        └── MyFont.woff2
```

建议在 ZIP 压缩包文件名中使用英文字母、数字、连字符（-）和下划线（_）。

例如：

```text
ocean-mint.zip
dark-glass.zip
baza-emerald.zip
```

### 导入时的 ID 生成

导入 ZIP 时，主题 ID 会根据 ZIP 文件名自动生成，并清理掉非法字符。

例如：

```text
Ocean Mint.zip
```

可能会获得如下 ID：

```text
ocean-mint
```

因此，建议提前为压缩包使用规范的名称。

这一点非常重要，因为主题 ID 经常用于系统路径、文件夹名称和主题选择逻辑中。如果压缩包命名不规范，创建的主题文件夹可能会使用不直观或不方便的标识符，这会给日后查找、删除和更新主题带来困难。

### 导入后会发生什么

导入后，16Launcher 通常会：
* 在 `themes` 目录中创建主题文件夹；
* 复制压缩包内的文件；
* 识别 `theme.json` 和 `style.css`；
* 将主题添加到可用主题列表中。

如果主题被成功识别，它将立即提供选择。如果压缩包存在问题（例如缺少 `style.css` 或 JSON 文件损坏），主题可能不会出现，或者显示异常。

## 5. 手动安装主题

你也可以在不使用 ZIP 导入的情况下手动安装主题。

步骤如下：

1. 为主题创建一个独立的文件夹。
2. 将 `theme.json` 和 `style.css` 添加到该文件夹中。
3. 根据需要添加图像、字体和其他资源。
4. 将文件夹复制到 `themes` 目录。
5. 打开 16Launcher 设置。
6. 进入自定义主题区域。
7. 选择已安装的主题。

例如：

```text
themes/
└── ocean-mint/
    ├── theme.json
    ├── style.css
    └── background.png
```

如果在复制文件时主题列表已经打开，可能需要重新打开 **启动器** 标签页或重启 16Launcher。

### 何时手动复制文件夹优于 ZIP 导入

在以下情况下，手动方式更有用：
* 主题处于开发阶段；
* 需要快速进行修改而无需重复压缩；
* 你想针对特定项目或本地资源集创建主题；
* 需要对文件夹内的文件进行精细配置。

同时，ZIP 导入更方便传播和分享给他人，因为整套主题可以轻松打包成一个文件。

### 正确文件夹结构的重要性

主题内部的文件不能只是“随意摆放”，而是必须严格位于对应的主题文件夹中。如果将文件直接放在 `themes` 根目录下而没有文件夹，16Launcher 可能无法识别它们。同理，如果 `theme.json` 和 `style.css` 层级过深，超出预期，也会导致失败。

基本规则很简单：每个主题都是一个独立的文件夹，内部包含 `theme.json` 和 `style.css`。

## 6. 从 16Launcher 内部创建主题

16Launcher 允许你直接在设置中创建新主题。

操作步骤：

1. 打开 **设置 → 启动器 → 自定义主题**。
2. 点击 **创建主题**。
3. 输入主题名称。
4. 16Launcher 将自动创建主题目录。
5. 目录中会生成默认的 `theme.json` 和 `style.css`。
6. 点击 **编辑 CSS**，在外部编辑器中打开 `style.css`。
7. 进行必要的修改。
8. 保存文件。

修改 CSS 后，请切换主题或重新选择该主题以应用更改。

### 主题是如何生成的

在创建主题时，16Launcher 会根据输入的名称自动生成文件夹，并创建基础文件。这种方式非常便利，因为：
* 无需手动构建目录结构；
* 拥有现成的初始模板；
* 可以快速测试想法；
* 方便保存主题并打包为 ZIP。

### 保存 CSS 后该做什么

修改文件后，许多用户期望更改能够立即生效。但在当前版本的 16Launcher 中，这并不总是自动发生的。因此，必须明确 CSS 编辑器并非实时预览服务。

### 修改 CSS 后更新主题

在当前版本的 16Launcher 中，尚未实现对 `style.css` 更改的实时自动追踪。

因此，编辑文件后，你需要：

* 切换到其他主题然后再切回来；
* 或者重启启动器。

这在主题开发过程中尤为重要，因为仅在文本编辑器中保存文件并不能保证界面会立即更新。

当某个主题处于激活状态时，16Launcher 只会加载一次 CSS。如果文件发生变更，用户环境并不总是能够识别出需要重新加载样式。因此，为了方便开发，请牢记以下循环流程：
1. 编辑 CSS；
2. 保存文件；
3. 切换主题或重启应用；
4. 检查效果。

### 推荐的开发习惯

在开发的早期阶段，建议：
* 进行微小的修改；
* 每次保存后检查效果；
* 一次仅应用一种样式；
* 使用尽量精简的选择器；
* 避免激进的全局重写，以免破坏界面布局。

## 7. 主题标识符与显示名称

每个主题都有两个不同的名称：

1. **主题 ID** — 目录的技术名称；
2. **主题名称** — 显示给用户的名称。

这两个值用途不同，不应视为同一个概念。

### 7.1. 主题 ID

ID 是磁盘上主题文件夹的名称。

例如：

```text
ocean-mint/
```

这里的 `ocean-mint` 就是主题的 ID。

建议遵循规范：

* 使用英文字母；
* 必要时使用数字；
* 使用 `-` 和 `_`；
* 请勿使用空格；
* 请勿使用特殊字符；
* 优先使用小写字母；
* 使用简短且含义明确的名称。

推荐示例：

```text
ocean-mint
dark-glass
baza-emerald
my-theme
theme_01
```

不建议的示例：

```text
My Theme!!!
theme 1
Cool Theme (final)
new-theme-中文
```

通过 **创建主题** 按钮创建主题时，16Launcher 会根据输入的名称自动生成 ID。

例如：

```text
Ocean Mint
```

将被转换为：

```text
ocean-mint
```

导入 ZIP 时，标识符会基于 ZIP 压缩包的文件名生成。

### 7.2. 显示名称

显示名称在 `theme.json` 文件的 `name` 字段中指定。

与 ID 不同，此名称直接面向用户。

在此名称中可以使用：
* 非拉丁字符（如中文等）；
* 空格；
* 大写字母；
* 特殊符号；
* UTF-8 支持的其他字符。

例如：

```json
{
  "name": "翡翠海洋",
  "author": "BAZA",
  "description": "适用于 16Launcher 的绿松石色主题",
  "version": "1.0"
}
```

在这种情况下：
* 主题 ID 可以是 `ocean-mint`；
* 显示名称为 `翡翠海洋`。

### 为什么区分 ID 和显示名称很重要

在发布主题、用户间共享主题以及后续维护时，这种区分尤为关键。磁盘上的文件夹应当便于系统识别和处理，而面向用户的名称则应直观易懂。

例如，磁盘上的目录名为 `dark-glass`，但在界面中可以向用户显示为 **毛玻璃暗黑**、**深色玻璃** 或 **Midnight Glass**。这可以在不破坏技术结构的前提下，使主题显得更加美观友好。

## 8. `theme.json` 格式

`theme.json` 文件包含主题的元数据。

最小示例：

```json
{
  "name": "我的主题",
  "author": "你的名字",
  "description": "主题的简短描述",
  "version": "1.0"
}
```

支持的字段：

| 字段 | 用途 |
| --- | --- |
| `name` | 界面中显示的主题名称 |
| `author` | 主题作者 |
| `description` | 简短描述 |
| `version` | 主题版本 |

所有字段都是可选的。但是，特别是当主题准备分发时，建议至少填写 `name`、`author`、`description` 和 `version`。

如果未指定 `name` 或其为空，界面可能会直接使用主题的目录名称。

### 什么是主题 Metadata

`theme.json` 文件不仅仅是为了界面展示好看，它还是主题的描述说明，用于界面识别和便捷管理。如果主题在用户之间分发，每个压缩包内带有清晰的元数据（名称、作者、版本、简述）将非常有帮助。

### 主题版本

对于版本号，建议使用清晰规范的格式：

```text
1.0
```

或：

```text
1.2.0
```

当主题发生重大变更时，建议提高版本号，以便用户能够轻松区分新旧版本。

如果主题被多个用户下载、更新或分享，这一点尤为重要。统一的版本格式有助于更好地追踪变更、对比更新，并了解主题是否与当前启动器版本兼容。

### 文件编码

`theme.json` 必须保存为 **UTF-8** 编码。

在使用非 ASCII 字符（如中文、俄文等）时，这一点至关重要。错误的编码可能导致名称、作者或描述显示为乱码。

如果文件保存为 ANSI、UTF-16 或其他编码，经常会出现 UTF-8 格式问题。这可能导致：
* 字符被替代/损坏；
* 出现无法读取的字符串；
* 名称变形；
* 加载时报错。

因此，在发布主题之前，务必确认文件已使用 UTF-8 编码打开并保存。

## 9. `style.css` 格式

外观的主要配置在 `style.css` 文件中完成。

这是一个普通的 CSS 文件，因此你可以使用 16Launcher 界面支持的标准 CSS 属性、选择器、变量、渐变、图像、字体以及其他 CSS 特性来创建主题。

基础示例：

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
  border-color: rgba(16, 185, 129, 0.35) !important;
}

.accent-bg {
  background: linear-gradient(135deg, #34d399, #059669) !important;
}

.interactive-press {
  border-radius: 16px !important;
}

.sidebar-icon-active {
  color: #6ee7b7 !important;
}
```

### 为什么主题 CSS 文件必须命名为 `style.css`

因为 16Launcher 指定将该文件名作为用户主样式来源。重写默认外观的规则全都在此文件中定义。

### 如何理解主题中的 CSS

在主题中，你可以使用：
* 类选择器；
* CSS 变量；
* 伪类；
* `background`、`color`、`border`、`border-radius`、`opacity`、`box-shadow`；
* 用于图像的 `url(...)`；
* 用于自定义字体的 `@font-face`。

但请记住，16Launcher 自身使用的类可能具有更高的优先级。因此，某些属性可能需要增加 `!important` 才能正确生效。

### 使用 `!important`

16Launcher 的默认样式优先级可能高于自定义主题的规则。

在这种情况下，可能需要使用 `!important`。

例如：

```css
.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
}
```

切勿无差别地为所有属性都加上 `!important`。建议先检查普通的 CSS 规则是否能正常生效。

滥用 `!important` 可能会导致：
* 代码维护变得困难；
* 后期修改极其麻烦；
* 与应用程序的更新产生冲突；
* 意外重写了不该修改的元素。

因此，`!important` 应当精准使用在确实存在优先级冲突的地方。

## 10. 16Launcher 的核心选择器

在主题中可以使用以下类和 CSS 变量。

| 选择器 | 用途 |
| --- | --- |
| `.glass-panel` | 界面的主玻璃面板 |
| `.glass-chip` | 小型芯片 (Chip) 和徽章 |
| `.interactive-press` | 可点击元素和按钮 |
| `.accent-bg` | 强调背景，包含部分按钮 |
| `.accent-border` | 强调边框 |
| `.accent-chip` | 强调芯片 |
| `.sidebar-icon-active` | 侧边栏活动图标 |
| `:root` | 定义 CSS 变量的根元素 |
| `--accent-color` | 主强调色 |

可用类的集合可能会随着 16Launcher 的更新而调整。因此，在开发复杂主题时，建议在启动器更新后检查其兼容性。

### 如何使用选择器

如果主题需要更改面板的整体背景，适合使用 `.glass-panel`。如果需要突出按钮，通常使用 `.interactive-press` 或 `.accent-bg` 就足够了。对于图标和侧边栏活动元素，请使用 `.sidebar-icon-active`。

### 找不到所需的类时怎么办

如果没有找到特定的类，可以使用更通用 选择器，但请注意，全局规则可能会意外影响到你原本不想修改的元素。

例如，你可以为所有按钮设置颜色或修改整块面板的背景，但这可能会作用于多个界面组件。因此，为了保持主题精细干净，最好：
* 使用具体明确的类；
* 组合选择器；
* 在应用样式后检查视觉效果；
* 避免“盲目重绘整个应用”。

### CSS 变量

变量通过 `:root` 应用：

```css
:root {
  --accent-color: #10b981;
}
```

这非常方便，因为：
* 可以在一处修改颜色；
* 无需重写几十条规则；
* 主题维护更容易；
* 更轻松地创建不同的配色方案。

需要注意的是，并非 16Launcher 中的所有元素都仅依赖单一变量。有时界面的某一部分会直接绑定类，而另一部分则通过自身的变量生效。

## 11. 使用图像

你可以在主题中添加自定义图像。

例如：

```text
ocean-mint/
├── theme.json
├── style.css
└── background.png
```

之后即可在 `style.css` 中引入该图像：

```css
.glass-panel {
  background-image: url(background.png) !important;
  background-size: cover !important;
}
```

资源路径必须是**相对路径**。

如果图像位于子文件夹中：

```text
ocean-mint/
├── theme.json
├── style.css
└── images/
    └── background.png
```

请使用：

```css
.glass-panel {
  background-image: url(images/background.png) !important;
}
```

16Launcher 会解析相对 `url(...)` 并将其转换为指向主题资源的有效路径。

### 为什么不能使用绝对路径

对于主题的本地文件，请勿使用特定计算机上的绝对路径，例如：

```text
C:\Users\User\Desktop\background.png
```

将主题分享给他人后，此类路径将无法工作。

绝对路径的缺点：
* 绑定到特定设备；
* 依赖于具体的系统用户名；
* 依赖于文件的具体位置；
* 无法迁移到其他电脑；
* 破坏了主题的可移植性。

### 使用图像时的注意事项

使用背景图像时应注意：
* 文件体积不宜过大；
* 为适应响应式界面，最好使用合适的分辨率；
* 可以使用 `background-size: cover` 来填满区域；
* 建议使用符合主题整体风格的背景图；
* 对于活动元素，图片不宜过于杂乱，以免干扰界面阅读。

有时采用以下组合效果更好：
* 半透明背景；
* 柔和的渐变；
* 细微的纹理图案；
而不是使用占用大量资源的大图。

## 12. 使用自定义字体

你可以在主题文件夹中添加自己的字体文件。

例如：

```text
ocean-mint/
├── theme.json
├── style.css
└── fonts/
    └── MyFont.woff2
```

可以使用 `@font-face` 引入字体：

```css
@font-face {
  font-family: "MyFont";
  src: url(fonts/MyFont.woff2);
}

body {
  font-family: "MyFont", sans-serif;
}
```

在分发主题前，请确保所用字体的许可证允许将其与其他文件一同再分发。

### 为什么许可协议很重要

自定义字体通常是主题设计的重要组成部分，但并非所有字体都可以无限制分发。如果字体商业受限或禁止打包在压缩包中，可能会引发版权争议。

建议：
* 使用允许再分发的字体；
* 如果许可协议要求，请在压缩包中附带许可证说明；
* 未经许可请勿使用他人资源；
* 提前确认分发权限。

### 字体的适用场景

自定义字体在以下情况下效果尤为突出：
* 试图模仿基于界面的特定风格；
* 具有较强的装饰性设计；
* 使用了强调标题或独特的视觉语言。

但如果字体过于沉重或在启动器界面中可读性差，即使设计再好也会打折扣。因此，在装饰性和实用性之间取得平衡非常重要。

## 13. 主题开发建议

在开发主题时，建议遵循以下规范：

### 使用 CSS 变量

如果主题中有多个元素使用同一种颜色，最好集中定义一次：

```css
:root {
  --accent-color: #10b981;
}
```

这极大地简化了日后对配色方案的修改。

使用变量的好处在于：
* 只需修改一个颜色值，所有关联元素同步更新；
* 更轻松地制作替代主题；
* 更容易在多条规则中维持统一的调色板；
* 代码结构更清晰。

### 不要修改 16Launcher 的系统文件

所有修改都必须限制在主题自己的文件夹内。

切勿通过修改应用程序本身的系统文件来实现视觉样式。

这一点非常重要，原因有二：
1. 系统文件的修改可能会在启动器更新后丢失；
2. 这种修改往往会破坏应用程序的完整性。

主题应当与项目主代码隔离，存放在 16Launcher 能够识别和支持的独立目录中。

### 使用相对路径

对于图像和字体，请使用相对路径：

```css
url(images/background.png)
```

而不是绑定到特定计算机的路径。

这是主题分发的核心规则之一。只有这样，主题才能成功发送给其他用户并在其他设备上正常加载。

### 安装后进行全面测试

在分发主题之前，建议检查：
* 所有面板的显示情况；
* 按钮外观；
* 活动元素；
* 背景图像；
* 自定义字体；
* 重新启动后的主题工作状态；
* ZIP 压缩包的完整性。

在使用自定义主题时，不仅要确认样式文件被成功加载，还要确保整体界面看起来协调无误。不要仅凭单个元素变色就下结论，务必确保整个设计的完整性。

### 初学者不要一开始就制作过于复杂的主题

新手最常见的错误就是试图一上来就做出包含复杂特效、阴影、动画和大量资源的“高级”设计。这往往会导致：
* 极其繁琐的调试过程；
* CSS 样式冲突；
* 界面元素可读性变差；
* 启动器更新后难以维护。

建议循序渐进：
* 先更改主颜色；
* 调整背景；
* 解决可读性问题；
* 最后再丰富细节。

## 14. 如何分享主题

建议将主题打包为 ZIP 压缩包进行分发。

操作步骤：

1. 打开主题目录。
2. 确认 `theme.json` 和 `style.css` 存在。
3. 检查附加的图像和字体。
4. 创建 ZIP 压缩包。
5. 将压缩包发送给其他用户。

你可以直接对主题文件夹进行打包：

```text
ocean-mint.zip
└── ocean-mint/
    ├── theme.json
    ├── style.css
    └── background.png
```

也可以将主题文件直接放在压缩包根目录下：

```text
ocean-mint.zip
├── theme.json
└── style.css
```

建议使用主题 ID 作为压缩包的文件名：

```text
ocean-mint.zip
```

这有助于简化主题识别，并在导入时生成正确的 ID。

接收者可以通过以下路径安装主题：

**设置 → 启动器 → 自定义主题 → 导入 ZIP**

### 打包的重要性

ZIP 压缩包是传输主题的通用标准。它能够：
* 将所有文件归档为一个整体；
* 方便通过邮件、聊天工具、社区或论坛快速发送；
* 保持完整的文件夹结构；
* 简化安装流程，无需手动复制文件。

### 打包建议

发送主题前建议：
* 检查压缩包内无无关文件；
* 确保所有路径保持正确；
* 确认未包含临时文件或系统缓存文件；
* 检查 ZIP 文件名是否规范；
* 确认 `theme.json` 和 `style.css` 处于预期的位置。

## 15. 删除主题

可以直接在 16Launcher 界面中删除已安装的主题：

1. 打开自定义主题列表。
2. 选择要删除的主题。
3. 点击 **删除主题**。
4. 确认删除。

此外，你也可以从 `themes` 目录中手动删除主题文件夹。

### 何时需要手动删除

在以下情况下，手动删除非常实用：
* 需要快速清理主题目录；
* 主题不再使用；
* 需要修复损坏文件夹带来的问题；
* 需要删除未在界面中显示的残留快照。

但手动删除时请确认：
* 文件夹确实不再需要；
* 该主题当前未被选为活动主题；
* 删除后应用不需要重新选择主题。

### 内置主题

某些随 16Launcher 一起发布的主题可能会在下次启动应用程序时自动恢复。

例如，如果你删除了内置的 `example-theme`，启动器在检测到对应文件夹缺失后，可能会自动从内置资源中重新复制一份。

这意味着内置主题并不完全等同于“永久性用户主题”，它们可能会从应用的基础资源中重新加载。因此，用户需要区分：
* 手动安装的用户主题；
* 可能会自动恢复的内置主题。

## 16. 常见问题

### 主题未显示在列表中

请检查以下几点：
* 主题文件夹是否存在；
* 是否包含 `theme.json`；
* 是否包含 `style.css`；
* 这些文件是否直接位于主题文件夹内；
* JSON 格式是否正确；
* 主题是否放在了正确的 `themes` 目录中。

正确结构：

```text
themes/
└── my-theme/
    ├── theme.json
    └── style.css
```

如果缺少文件，应用程序将无法识别主题。遇到此类情况，请仔细核对目录结构。

### 导入后生成了错误的 ID

导入 ZIP 时，ID 会根据压缩包文件名自动生成。

例如：

```text
My Cool Theme.zip
```

可能会生成一个与预期不符的 ID。

如果需要修改 ID，请重命名 ZIP 压缩包并重新导入主题。

有时用户希望 ID 与主题名称完全一致。这当然可以，但由于导入时 ID 是根据文件名自动提取的，因此提前为压缩包选择一个规范的文件名是避免问题最简单的方法。

### CSS 未生效

可能的原因：
1. CSS 选择器书写错误。
2. 默认规则具有更高的优先级。
3. 在需要的地方未添加 `!important`。
4. 修改文件后未重新应用主题。
5. 更改未在编辑器中保存。

修改 `style.css` 后，请切换主题或重启 16Launcher。

这是最常见的问题之一。用户修改了 CSS 但界面毫无变化，原因往往在于：
* 选择器实际上与目标元素不匹配；
* 旧规则覆盖了新规则；
* 主题没有被重新刷新；
* 编辑器没有成功保存修改；
* 文件在不同的编码或错误的文件夹中被编辑。

### 图像未显示

请检查：
* 文件是否存在；
* 相对路径是否正确；
* 文件名的大小写是否一致；
* 文件是否位于主题文件夹内部。

例如：

```css
background-image: url(images/background.png);
```

要求存在以下文件：

```text
images/background.png
```

同时请注意，文件名大小写在某些操作系统（如 Linux）上是敏感的。如果实际文件名为 `Background.png`，而在 CSS 中写成了 `background.png`，可能会导致加载失败。

### 还原设置后主题消失

还原重置设置可能会取消选中的主题或恢复为默认外观。

此时，`themes` 目录中的主题文件夹本身通常依然保留。

在这种情况下，只需打开自定义主题列表并重新选择该主题即可。

还原设置并不意味着删除了主题文件。它通常只是重置了当前激活的选择和用户参数列表。也就是说，磁盘上的实际主题依然存在，只是不再处于激活状态。

## 17. 推荐的成品主题结构

分发主题时，建议采用以下结构：

```text
ocean-mint/
├── theme.json
├── style.css
├── images/
│   └── background.png
└── fonts/
    └── MyFont.woff2
```

`theme.json` 示例：

```json
{
  "name": "翡翠海洋",
  "author": "BAZA",
  "description": "适用于 16Launcher 的绿松石色主题",
  "version": "1.0.0"
}
```

`style.css` 示例：

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
  border-color: rgba(16, 185, 129, 0.35) !important;
}

.accent-bg {
  background: linear-gradient(135deg, #34d399, #059669) !important;
}

.accent-border {
  border-color: rgba(16, 185, 129, 0.5) !important;
}

.interactive-press {
  border-radius: 16px !important;
}

.sidebar-icon-active {
  color: #6ee7b7 !important;
}
```

### 为什么推荐这种结构

因为这种结构：
* 逻辑清晰；
* 对用户直观易懂；
* 易于传播分发；
* 方便编辑修改；
* 能够将不同类型的资源分门别类存储；
* 导入时不会引起混淆；
* 符合通用的主题包标准。

## 18. 主题发布前检查清单

在将主题发送给其他用户之前，建议检查以下事项：

* [ ] 主题文件夹具有规范的 ID，例如 `my-theme`。
* [ ] 文件夹内包含 `theme.json`。
* [ ] 文件夹内包含 `style.css`。
* [ ] `theme.json` 已保存为 UTF-8 编码。
* [ ] 在 `theme.json` 中指定了清晰的主题名称。
* [ ] 填写的作者信息。
* [ ] 填写了版本号。
* [ ] 填写了简短描述。
* [ ] 所有图像和字体文件均位于主题文件夹内部。
* [ ] CSS 中对资源的引用均使用相对路径。
* [ ] 主题在 16Launcher 中显示正常。
* [ ] 所有必要的 CSS 规则均已成功应用。
* [ ] 重启启动器后主题能够重新正确应用。
* [ ] ZIP 压缩包能通过 **导入 ZIP** 正常导入。
* [ ] 压缩包内未包含与主题无关的冗余文件。

### 为什么发布前检查很重要

发布主题不单单是“保存并发送”。结构、路径、编码或选择器上的微小错误都可能导致主题无法正常工作。检查清单有助于及时发现这些隐患，避免尴尬。

## 19. 快速上手

你可以在几分钟内创建你的第一个主题。

### 第一步：创建主题

打开：

**设置 → 启动器 → 自定义主题 → 创建主题**

输入名称，例如：

```text
我的主题
```

16Launcher 将自动创建主题目录和所需文件。

### 第二步：打开 CSS

点击 **编辑 CSS**。

系统将打开文件：

```text
style.css
```

### 第三步：添加样式

示例：

```css
:root {
  --accent-color: #10b981;
}

.glass-panel {
  background: rgba(6, 40, 30, 0.75) !important;
}

.accent-bg {
  background: #10b981 !important;
}
```

保存文件。

### 第四步：应用更改

将主题切换为 **默认**，然后再次选择刚刚创建的主题。

或者，你也可以完全重启 16Launcher。

之后 CSS 的修改就会生效。

### 第五步：准备分发主题

当设计完成后，打开主题文件夹并将其打包为 ZIP 压缩包。

推荐结构：

```text
my-theme.zip
└── my-theme/
    ├── theme.json
    └── style.css
```

打包好的压缩包可以发送给其他用户。他们只需使用 **导入 ZIP** 即可完成安装。

### 如何引导开发流程

刚开始时，最稳妥的顺序是：
* 先更改强调色；
* 让面板变暗或调整透明度；
* 调整 border-radius；
* 检查元素的视觉可读性；
* 然后再尝试实现更复杂的特效。

开发主题是一个循序渐进的调整过程。从基础的改动开始并随时观察视觉效果，要比试图一口吃个胖子容易得多。
